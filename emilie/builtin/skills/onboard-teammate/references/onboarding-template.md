# Onboarding guide template

1. **What this is** - purpose, users, main components (diagram or 5 lines).
2. **Day-one setup** - prerequisites, clone, install, configure env (`.env.example`), run, run tests; expected output; common errors and fixes.
3. **Daily workflow** - branch naming, commit style, running checks locally, opening a PR, review expectations, CI, release cadence.
4. **Map of the code** - directories and what lives there, entry points, where to add a feature/test/doc.
5. **Conventions** - style, naming, error handling, logging, testing approach.
6. **Where to ask** - channels, owners per area, on-call, how decisions are recorded (ADRs).
7. **First tasks** - 3-5 scoped items with starting files and acceptance criteria.
8. **Glossary** - domain terms and acronyms.
